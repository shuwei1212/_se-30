# 報價工坊 QuoteDesk

> 給自由工作者與小型工作室的「報價單 + 定價試算」工作台。  
> 先算出不虧本的價格，再產出專業、可列印的報價單。

## 一句話說明價值

**多數報價工具只幫你把數字排漂亮；QuoteDesk 幫你在報價前先知道「這個價格會不會做白工」，再把結果變成一張可追蹤、可列印的正式報價單。**

---

## 1. 為什麼做這個專案

### 問題

接案族與小型工作室每天都會遇到同一件事：報價。

但實務上常見的流程是：

1. 打開舊的 Excel 或 Word 檔，複製貼上。
2. 憑感覺填一個數字，深怕報太高嚇跑客戶、報太低又虧錢。
3. 忘了把稅金、管理成本、來回修改、設備折舊算進去。
4. 報價單散落在資料夾裡，過幾天不知道哪一份成交、哪一份該追蹤。
5. 好不容易成交，才發現扣掉成本與稅金後，時薪比打工還低。

### 目標使用者

- 剛開始接案的軟體工程師、設計師、剪輯師、攝影師
- 1 到 5 人的小型工作室
- 需要經常報價、但不想導入複雜 ERP 或會計系統的個人工作者
- 台灣在地使用者：需要營業稅、統一編號、國字大寫金額、匯款資訊

### 為什麼是現在

- 接案平台與自由工作者數量持續增加，報價頻率變高。
- 大型會計／ERP 系統對個人來說太重，Excel 又太容易出錯。
- 多數人已經習慣瀏覽器工具，但不希望把客戶與價格資料上傳到不信任的服務。
- 台灣本地化需求（營業稅、國字大寫）在國際工具中通常支援不足。

## 2. 價值主張

### 使用價值：自己就是使用者

我自己接案時最常卡住的三件事，就是這個專案直接解決的問題：

1. **不知道怎麼報價**  
   「估價小幫手」把工時、時薪、其他成本、管理負擔、風險預備、目標利潤與稅金拆開計算，讓價格有依據，而不是憑感覺。

2. **報價單做得不夠專業**  
   一鍵產生含賣方資訊、客戶資訊、項目明細、折扣、稅額、訂金、尾款、國字大寫金額與條款的報價單，可直接列印或存成 PDF。

3. **報價之後就忘了追蹤**  
   每份報價都有草稿／已送出／已成交／已婉拒狀態，儀表板自動計算報價總額、已成交金額、成交率與待追蹤案件。

對使用者的實際好處：

- 每份報價可節省約 10 到 30 分鐘的文書與計算時間。
- 降低漏算稅金、訂金、尾款的機率。
- 降低「低估成本」導致做白工的風險。
- 資料留在本機，不需要把客戶名單與價格交給第三方。
- 可匯出 JSON 備份，不怕被單一服務綁死。

### 商業價值：能賺錢，而且商業模式清楚

#### 已知商業模式（市場上已被驗證）

國際上有以報價／請款為核心的 SaaS，例如 Invoice Simple、Bonsai、Zoho Invoice 等，常見模式包含：

- **Freemium 訂閱**：免費方案限制報價數量或功能，付費解鎖無限報價、品牌自訂、追蹤與報表。
- **按席位收費**：工作室版本依人數計價。
- **年繳折扣**：提高留存與現金流。
- **加值服務**：匯入舊資料、客製欄位、教育訓練、品牌白牌。

#### 本專案可延伸的商業模式

| 模式 | 內容 | 收費想像 |
|------|------|----------|
| 訂閱制 SaaS | 雲端版、多人協作、自動備份、成交追蹤 | 個人 NT$149/月；工作室 NT$399/月 |
| 買斷 / 原始碼授權 | 賣給想自行部署的學校、工作室、接案者 | NT$1,990 起 |
| 接案客製 | 依產業新增欄位、串接金流、電子簽章、ERP | NT$15,000 起／案 |
| 教育與模板 | 接案定價課程、報價模板包、顧問 | 課程／模板單價銷售 |
| 白牌 / 經銷 | 讓會計師、接案社群、加速器貼牌使用 | 授權金＋分潤 |

#### 可驗證的商業假設

1. 接案者願意為「不會報太低」的工具付費，因為一次低估的損失就超過一年訂閱費。
2. 台灣在地化（營業稅、國字大寫、統編）是國際工具的空缺。
3. Local-first 對重視客戶隱私的自由工作者有吸引力。
4. 報價單 → 成交追蹤 → 成交率分析，能形成使用黏著度與升級動機。

### 差異化

| 一般報價單產生器 | QuoteDesk |
|------------------|-----------|
| 只產生文件 | 先做定價試算，再產生文件 |
| 價格靠使用者自己填 | 把成本、管理負擔、風險、利潤與稅金拆開算 |
| 國際工具較少處理台灣稅務與國字大寫 | 內建營業稅、統一編號、國字大寫、匯款資訊 |
| 資料多在雲端 | Local-first，資料留在自己的電腦，可匯出 JSON |
| 沒有成交回饋 | 狀態追蹤與成交率，讓下一次報價更準 |
| 相依大量套件 | 零第三方依賴，只使用 Node.js 內建模組，易部署、易稽核 |

## 3. 核心功能

- **儀表板**：報價總額、已成交金額、成交率、待追蹤數量與最近報價。
- **報價單管理**：建立、編輯、複製、刪除、搜尋、依狀態篩選。
- **即時金額試算**：新增／刪除項目時，前端即時更新小計、折扣、稅額、總計、訂金與尾款。
- **伺服器端重算**：所有金額由伺服器重新計算，不信任前端送來的數字。
- **台灣在地化**：營業稅率、統一編號、國字大寫金額（壹仟貳佰參拾肆元伍角陸分整）。
- **估價小幫手**：工時 × 時薪 + 其他成本 + 管理負擔 + 風險預備 + 目標利潤 + 稅金，算出建議報價與毛利率。
- **專業列印版**：A4 列印樣式，可直接「列印 / 存成 PDF」。
- **成交狀態**：草稿、已送出、已成交、已婉拒；儀表板自動統計成交率。
- **公司設定**：賣方資訊、匯款資訊、預設稅率、編號前綴與預設條款。
- **資料可攜**：`/export` 匯出 JSON 備份。
- **範例資料**：第一次啟動自動建立兩份示範報價，開箱即可展示。

## 4. 快速開始

需求：Node.js 20 以上（使用內建模組，不需要 `npm install`）。

```sh
cd 03
npm start
```

打開 <http://127.0.0.1:3000>。

第一次啟動會在 `data/db.json` 建立範例資料。若要重新開始，停止伺服器後刪除 `data/db.json` 再啟動即可。

### 環境變數

| 變數 | 說明 | 預設值 |
|------|------|--------|
| `PORT` | 監聽埠 | `3000` |
| `HOST` | 監聽位址 | `127.0.0.1` |
| `DB_FILE` | JSON 資料檔路徑 | `data/db.json` |

範例：

```sh
PORT=8080 DB_FILE=./data/demo.json npm start
```

> 注意：目前是單人、本機優先的 MVP，沒有登入機制。請不要直接暴露到公網；若要部署到雲端，請先加上帳號驗證、CSRF 防護與正式資料庫。

## 5. 5 分鐘 Demo 腳本

1. 開啟首頁，看到兩份範例報價與統計卡片。
2. 到「公司設定」填入自己的工作室資訊與匯款帳號。
3. 到「估價小幫手」，輸入預估工時與時薪，按「重新試算」。
4. 按「用這個價格建立報價單」，系統自動帶入一個報價項目。
5. 補上客戶資料、調整項目與折扣，觀察右側金額即時更新。
6. 儲存後進入報價單，按「列印 / 存 PDF」。
7. 回到報價單列表，把狀態改為「已成交」，回儀表板看成交率變化。
8. 到 `/export` 下載 JSON 備份。

## 7. 技術架構

```text
03/
├── package.json
├── README.md
├── .gitignore
├── data/                  # 執行時產生的 JSON 資料（git 忽略）
├── public/
│   ├── styles.css         # 版面、響應式與 A4 列印樣式
│   ├── app.js             # 前端互動：動態項目、即時試算、列印、刪除確認
│   └── domain.js          # 瀏覽器與伺服器共用的純邏輯
├── src/
│   ├── server.js          # 啟動入口
│   ├── app.js             # 路由、表單解析、HTTP 回應與靜態檔案
│   ├── db.js              # JSON 儲存、驗證、報價商業邏輯
│   ├── domain.js          # 重新匯出共用邏輯
│   ├── seed.js            # 範例資料
│   └── views.js           # 伺服器端 HTML 樣板
└── test/
    ├── domain.test.js
    └── app.test.js
```

### 設計決策

1. **零第三方依賴**  
   只使用 `node:http`、`node:fs`、`node:path`、`node:crypto` 等內建模組。部署簡單、供應鏈風險低，也方便在課堂或 Docker 環境重現。

2. **Server-Side Rendering + 漸進式增強**  
   沒有前端框架。頁面即使關閉 JavaScript 仍可送出表單；JavaScript 只負責即時試算、動態新增項目與列印等體驗加值。

3. **共用 domain 模組**  
   `public/domain.js` 同時被瀏覽器與 Node 匯入，確保前端預覽與伺服器實際儲存的金額邏輯一致，避免「畫面上看到的」和「存進去的」不同。

4. **伺服器是唯一真相來源**  
   前端送出的只有數量與單價，小計、折扣、稅額、總計、訂金一律由伺服器重新計算與驗證。

5. **JSON 檔案儲存**  
   MVP 階段不需要資料庫；資料可讀、可備份、可匯出。未來可替換成 SQLite/PostgreSQL，`db.js` 的介面即為替換邊界。

6. **報價單快照**  
   建立報價單時保存當下的賣方資訊，之後修改公司設定不會意外改動已送出的歷史報價。

```json
      ],
      "discountType": "amount",
      "discountValue": 5000,
      "taxRate": 5,
      "deposit": 30000,
      "notes": "",
      "terms": "",
      "seller": { "companyName": "好點子設計工作室" },
      "createdAt": "2026-11-10T00:00:00.000Z",
      "updatedAt": "2026-11-10T00:00:00.000Z"
    }
  ]
}
```

金額計算規則：

1. 每列金額 = `round(數量 × 單價)`。
2. 小計 = 各列金額加總。
3. 折扣：固定金額會限制在小計以內；百分比限制在 0–100%。
4. 稅額 = `round((小計 − 折扣) × 稅率 / 100)`。
5. 總計 = 小計 − 折扣 + 稅額。
6. 訂金限制在 0 到總計之間；尾款 = 總計 − 訂金。

## 10. 隱私與安全

- 所有 HTML 輸出都經過跳脫，避免 XSS。
- 設定 `Content-Security-Policy`、`X-Content-Type-Options`、`X-Frame-Options`、`Referrer-Policy`。
- 靜態檔案有路徑穿越防護。
- 表單有伺服器端驗證與大小上限。
- 沒有第三方追蹤、沒有外部 CDN、沒有將資料送到雲端。
- 報價編號、賣方資訊、金額皆由伺服器產生。

### 目前的限制

- 沒有登入與權限管理，僅適合本機或受信任網路。
- 沒有 CSRF token（因為目前是單人本機工具；上雲前必須補上）。
- JSON 檔案不適合高併發或多人同時寫入。
- 尚未串接電子簽章、金流、發票或會計系統。

## 12. 對應課程作業

這是軟體工程課程第 3 週「有價值專案」的實作。

選擇這個題目的理由：

- **使用價值**：自己就是接案者，報價與定價是每週都會遇到的痛點。
- **商業價值**：報價／請款 SaaS 已有明確商業模式，且台灣在地化與 local-first 仍有空間。
- **技術可展示性**：可在瀏覽器完整 demo，包含表單、計算、狀態管理、PDF 列印與測試。
- **可延伸性**：後續可接 Docker、網站測試、Cloudflare 部署等其他週次的作業。
