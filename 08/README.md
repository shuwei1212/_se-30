# 報價工坊 QuoteDesk Studio

> 給自由工作者與小型工作室的「報價、毛利、追蹤、收款」工作台。
>
> 不只知道報價多少，還知道這張報價划不划算、什麼時候該追、錢收到哪裡了。

## 一句話說明價值

**QuoteDesk Studio 把報價單從「一份文件」變成一個可追蹤的接案流程：先算成本與毛利，再產生報價，接著追蹤、成交、收款，最後用數據回看哪些案件真的值得接。**

---

## 1. 這個版本多了什麼

`08/` 以 `03/` 的 QuoteDesk 為基礎，保留原本的 local-first、零依賴與可列印報價單，再往下加深五個層次：

| 層次 | `03/` 的基礎 | `08/` 的加深 |
|------|--------------|--------------|
| 成本 | 只有售價與稅金 | 每個項目可填內部成本，計算成本、毛利、毛利率 |
| 追蹤 | 只有報價狀態 | 每份報價有追蹤日、追蹤備註、逾期／7 天內狀態 |
| 收款 | 只有訂金與尾款 | 可登記多筆收款、計算已收／待收／超收，並防止超收 |
| 版本 | 編輯後直接覆蓋 | 每次儲存保留上一版，可還原歷史版本（最多 20 筆） |
| 分析 | 報價總額、成交率 | 增加毛利、低毛利案件、待追蹤、逾期、待收款 |
| 匯出 | JSON 備份 | 增加 CSV，可直接進試算表做分析 |

這些功能都維持同一個原則：**資料留在本機、伺服器端重算、零第三方 runtime 依賴。**

---

## 2. 為什麼做這個專案

### 問題

接案族與小型工作室的報價流程，常見問題不是「不會做表」，而是：

1. 報價時只看售價，沒有把工時、外包、素材、管理成本算進去。
2. 成交後才發現毛利很低，甚至做越久虧越多。
3. 報價送出後散落在信箱與資料夾，忘記哪一份該追。
4. 客戶分兩次付款，訂金、尾款、待收金額靠印象記。
5. 想回頭比較「哪種類型的案件值得接」，卻沒有結構化資料。

### 目標使用者

- 剛開始接案的軟體工程師、設計師、剪輯師、攝影師、顧問
- 1 到 5 人的小型工作室
- 需要經常報價，但不想導入複雜 ERP 或會計系統的個人工作者
- 台灣在地使用者：需要營業稅、統一編號、國字大寫金額、匯款資訊

### 設計目標

- **先算清楚再生產文件**：成本與毛利是報價的一部分，不是事後才補。
- **追蹤要能被看見**：逾期與即將到期的報價要主動出現在儀表板。
- **收款要有帳**：每一筆收款都有日期、金額、方式與備註。
- **改錯要能回頭**：版本紀錄讓誤改、誤刪有補救空間。
- **匯出不能被綁死**：JSON 備份、CSV 分析，資料永遠拿得回來。

## 3. 核心功能

### 儀表板

- 報價總額（排除已婉拒）
- 已成交金額與成交毛利率
- 成交率（已成交／已成交＋已婉拒）
- 待追蹤數量與逾期數量
- 預估毛利、整體毛利率、低毛利案件數
- 待收款與已收款
- 本週追蹤清單：已送出且 7 天內到期或已逾期的報價
- 最近報價

### 報價管理

- 建立、編輯、複製、刪除報價單
- 依關鍵字搜尋編號、客戶、專案、項目、追蹤備註
- 依狀態篩選：草稿、已送出、已成交、已婉拒
- 依追蹤狀態篩選：需追蹤、已逾期、7 天內、未結案
- 每日自動遞增報價編號，例如 `Q20261111-001`

### 成本與毛利

- 每個報價項目都有「內部成本」欄位，不會出現在列印給客戶的版本。
- 伺服器與前端共用同一套 `computeTotals()`，即時顯示：
  - 小計、折扣、稅額、總計
  - 內部成本、預估毛利、毛利率
  - 訂金、尾款
- 毛利率低於公司設定的門檻時，表單與報價頁會顯示警示。
- 毛利以「折扣後、未稅金額」為分母，避免把營業稅誤算成收入。

### 追蹤

- 每份報價可設定下次追蹤日與追蹤備註。
- 追蹤狀態：
  - `待追蹤`：追蹤日尚未到，且超過 7 天
  - `7 天內`：7 天內到期
  - `已逾期`：追蹤日已過
  - `已結案`：已成交或已婉拒
- 新報價的追蹤日預設為報價日後 N 天，可在公司設定調整。
- 列表、儀表板、報價頁都能看到追蹤狀態。

### 收款

- 每份報價可登記多筆收款，欄位包含日期、金額、方式、備註。
- 自動計算已收、待收、超收。
- 收款金額不可超過報價總計，避免誤輸入。
- 已婉拒的報價不能登記收款。
- 可刪除單筆收款紀錄。

### 版本紀錄

- 每次編輯儲存前，系統會保留上一版快照。
- 版本紀錄包含時間、版本原因、當時總計。
- 可從版本紀錄還原到指定版本；還原前會先把目前內容存成另一個版本。
- 每份報價最多保留 20 個歷史版本，避免 JSON 檔無限成長。

### 列印與匯出

- A4 列印樣式，可直接「列印 / 存 PDF」。
- 列印版只包含給客戶的資訊；內部成本、毛利、追蹤、收款、版本紀錄都會隱藏。
- `/export` 匯出完整 JSON 備份。
- `/export.csv` 匯出報價 CSV，含成本、毛利、已收、待收與追蹤日。

### 公司設定

- 賣方名稱、統一編號、電話、Email、地址、匯款資訊
- 預設營業稅率、報價編號前綴、預設條款
- 低毛利警示門檻
- 預設追蹤天數
- 資料匯出入口

## 4. 快速開始

需求：Node.js 20 以上（使用內建模組，不需要 `npm install`）。

```sh
cd 08
npm start
```

打開 <http://127.0.0.1:3000>。

第一次啟動會在 `data/db.json` 建立三份示範資料，包含成本、付款與不同狀態。若要重新開始，停止伺服器後刪除 `data/db.json` 再啟動即可。

### 環境變數

| 變數 | 說明 | 預設值 |
|------|------|--------|
| `PORT` | 監聽埠 | `3000` |
| `HOST` | 監聽位址 | `127.0.0.1` |
| `DB_FILE` | JSON 資料檔路徑 | `data/db.json` |

範例：

```sh
PORT=8080 DB_FILE=./data/demo.json npm start
```

> 這是單人、本機優先的版本，沒有登入機制。請不要直接暴露到公網；若要部署到雲端，請先加上帳號驗證、CSRF 防護與正式資料庫。

## 5. 5 分鐘 Demo 腳本

1. 開啟首頁，看到三份範例報價、毛利統計與本週追蹤。
2. 到「公司設定」填入工作室資訊，設定低毛利門檻與預設追蹤天數。
3. 到「估價小幫手」輸入工時與成本，算出建議報價。
4. 用建議價格建立報價單，填入客戶資料與每個項目的內部成本。
5. 觀察右側即時計算的成本、毛利、毛利率與低毛利警示。
6. 儲存後進入報價頁，查看內部管理區塊的利潤、追蹤與收款。
7. 登記一筆收款，觀察已收與待收金額變化。
8. 編輯報價並儲存，回到報價頁查看版本紀錄，試著還原上一個版本。
9. 把狀態改為「已成交」，回首頁看成交金額、成交率與待收款。
10. 到 `/export.csv` 下載 CSV，用試算表檢查毛利與收款欄位。

## 7. 技術架構

```text
08/
├── package.json
├── README.md
├── .gitignore
├── data/                  # 執行時產生的 JSON 資料（git 忽略）
├── public/
│   ├── styles.css         # 版面、響應式、內部管理區塊與 A4 列印樣式
│   ├── app.js             # 前端互動：動態項目、即時成本／毛利、列印、刪除確認
│   └── domain.js          # 瀏覽器與伺服器共用的純邏輯
├── src/
│   ├── server.js          # 啟動入口
│   ├── app.js             # 路由、表單解析、HTTP 回應與靜態檔案
│   ├── db.js              # JSON 儲存、驗證、版本、付款、統計、匯出
│   ├── domain.js          # 重新匯出共用邏輯
│   ├── seed.js            # 三份示範資料
│   └── views.js           # 伺服器端 HTML 樣板
└── test/
    ├── domain.test.js     # 純邏輯測試
    ├── db.test.js         # store、版本、付款、統計、匯出
    └── app.test.js        # HTTP 與頁面整合測試
```

### 關鍵設計

1. **共用 domain**
   `public/domain.js` 同時被瀏覽器與 Node 匯入，前端預覽與伺服器權威計算使用同一套公式，避免顯示與實際儲存金額不一致。

2. **伺服器端重算**
   前端送出的數量、單價、成本、折扣、稅率都只當作輸入；實際金額一律由 `computeTotals()` 重算。

3. **JSON 持久化**
   單人使用情境下，JSON 足夠簡單、可備份、可人工檢查。`createStore(file)` 啟動時會正規化舊資料，缺少的新欄位會自動補上。

4. **版本快照**
   更新前先建立不含付款與版本本身的快照，還原時保留目前付款紀錄，避免把收款一起回滾。

5. **收款防超收**
   新增收款前先計算目前總計與已收金額，超過總計直接拒絕，避免資料不一致。

6. **列印與內部分離**
   所有內部管理資訊都放在 `.no-print` 區塊，列印時自動隱藏，客戶不會看到成本與毛利。

## 8. 資料模型（節錄）

```json
{
  "settings": {
    "companyName": "好點子設計工作室",
    "defaultTaxRate": 5,
    "quotePrefix": "Q",
    "lowMarginThreshold": 20,
    "followUpDays": 7
  },
  "quotes": [
    {
      "id": "uuid",
      "number": "Q20261111-001",
      "status": "sent",
      "issueDate": "2026-11-11",
      "validUntil": "2026-11-25",
      "followUpDate": "2026-11-18",
      "followUpNote": "詢問對方是否已收到報價",
      "internalNotes": "議價底線 45,000",
      "items": [
        {
          "description": "網站視覺設計",
          "qty": 1,
          "unit": "式",
          "unitPrice": 28000,
          "unitCost": 12000
        }
      ],
      "discountType": "amount",
      "discountValue": 5000,
      "taxRate": 5,
      "deposit": 30000,
      "payments": [
        {
          "id": "uuid",
          "date": "2026-11-11",
          "amount": 30000,
          "method": "匯款",
          "note": "簽約訂金"
        }
      ],
      "revisions": [
        {
          "id": "uuid",
          "at": "2026-11-11T09:30:00.000Z",
          "reason": "更新前版本",
          "snapshot": {}
        }
      ]
    }
  ]
}
```

### 金額定義

| 欄位 | 定義 |
|------|------|
| `subtotal` | 各項目數量 × 單價加總 |
| `discount` | 依折扣方式計算，折抵金額不可超過小計 |
| `afterDiscount` | 小計 − 折扣，也是毛利計算的收入基準 |
| `tax` | `afterDiscount × 稅率`，四捨五入到整數 |
| `total` | `afterDiscount + tax` |
| `costTotal` | 各項目數量 × 內部成本加總 |
| `grossProfit` | `afterDiscount − costTotal` |
| `margin` | `grossProfit / afterDiscount × 100` |
| `paidTotal` | 所有收款金額加總 |
| `balanceDue` | `max(0, total − paidTotal)` |
| `overpaid` | `max(0, paidTotal − total)` |

## 10. 設計取捨與限制

### 為什麼用 JSON，不用資料庫

- 單人、本機使用，資料量不大。
- 可直接備份、檢查、匯入。
- 零依賴，任何有 Node.js 的電腦都能跑。
- 缺點：沒有交易、沒有多人並發、沒有索引。若要多人或雲端版，應改用 SQLite/PostgreSQL。

### 為什麼毛利不含稅

營業稅是代收代付性質，不是收入。因此毛利率以 `afterDiscount` 為分母，而不是含稅總計。

### 為什麼版本只保留 20 筆

避免 JSON 檔因長期編輯無限膨脹。對一般報價流程來說，20 個歷史版本已足夠回看與補救。

### 為什麼超收直接阻擋

收款超過總計通常代表輸入錯誤或折扣未更新。與其允許超收再另外處理退款，不如在輸入時就阻擋。

### 已知限制

- 沒有登入、權限與多人協作。
- 沒有 CSRF token；目前依靠 local-first 與 `form-action 'self'` CSP。
- JSON 寫入是同步整檔寫入，極端大量資料時會變慢。
- 追蹤「7 天內」是固定窗口；公司設定的追蹤天數只影響新報價的預設追蹤日。
- CSV 匯出目前不包含逐筆收款明細，只有彙總欄位。
- 沒有電子簽章、金流串接、發票開立。
